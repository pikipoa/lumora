# infra.md — 開発インフラ（採否判断）

Lumora（旧称：Knowledge OS）

前提：Lumoraは認証必須の個人向けアプリ（Supabase Auth + React Native/Expo Web + Vercel）であり、古着ダンジョン（Shopify公開ストア、不特定多数がアクセス）とは脅威モデル・利用規模が異なる。この違いを踏まえた採否判断。

---

## 開発フローの原則（決定・2026-07-24）

「考える仕事はAI、決まった作業はGitHub Actions」という役割分担を、個別ツールの採否判断を超えた開発フローの原則として明文化する。

- **AIに任せる仕事**：新機能を作る／バグを修正する／設計を考える／テストコードを書く。判断が要る仕事
- **GitHub Actionsに任せる仕事**：テストの実行／コードチェック（ESLint等）／ビルド／デプロイ／リリースノート作成／成功・失敗の通知。決まりきった機械的な作業
- 現状（本セッション時点）はこの機械的な作業をAI（Claude Code）が都度手動で肩代わりしている（`tsc`/`jest`を実行してから`vercel --prod`を叩く、等）。これをGitHub Actionsへ移し、AIは「push」までを担当する形に変える

**Sentryも同じ原則の一部として明文化する**：エラー監視は単なる技術的なツール選定ではなく、**非エンジニアであるピキさんが、実際に起きたエラーの証拠（スタックトレース）を持ってAIに調査を依頼できる**という、この開発体制そのものを支える要素である。2026-07-24のクラッシュ調査（Wing→Realm遷移での`removeChild`エラー）で、ピキさんがSentryのスタックトレースを直接共有したことで、AI側の推測ベースの調査（コードを読んでの仮説検証）から一発で根本原因の特定に切り替わった実例がある。「エラー情報をしっかりとした証拠と一緒に提出できるのは非エンジニアにとって心強い」という位置づけを、今後もSentry導入を判断する上での中心的な理由として維持する。

## 採用する

| サービス | 理由 |
|---|---|
| GitHub | Claude Codeでの開発・コード履歴管理に必須 |
| Vercel | Expo Webビルドのホスティング先 |
| GitHub Actions（構想・2026-07-24、実装未着手） | push→テスト（`tsc --noEmit`・`jest`）→lint（`expo lint`）→ビルド確認（`expo export -p web`）→Vercelへデプロイ、という機械的な作業を自動化する。実装前に確認が必要な点：VercelのGitHub連携（push時自動デプロイ）が既に有効かどうか。有効な場合は二重デプロイを避けるため、GitHub連携をオフにしてActions側から`vercel deploy --prod`を明示的に呼ぶ形に変更する |
| Sentry | 当初はクライアント側4社パーサー・マーカー範囲調整UIという技術リスクの高い箇所のエラー可視化が目的だったが、サインアップ機能実装（2026-07-23）を機に、認証エラー・Edge Function（organize-markers/organize-wings）呼び出し失敗・Anthropicタイムアウトまで対象を拡張した。PIIマスキング（マーカー本文・メモ本文・メールアドレスは送らない、console breadcrumb無効化）を徹底した設計。詳細：`src/lib/sentry.ts`、`supabase/functions/_shared/sentry.ts`。上記「開発フローの原則」も参照（非エンジニアが証拠を持って報告できる仕組みとしての位置づけ） |

## 見送る（Phase1では不要）

| サービス | 理由 |
|---|---|
| Cloudflare | Vercel・Supabaseがそれぞれ自前でCDN/SSL/基本的なDDoS対策を持っている。公開LP開設や不特定多数の新規登録受付が始まったら再検討 |
| UptimeRobot | 監視対象になる「公開サーバー」が存在しない（SupabaseもVercelも自前でステータス監視を持つマネージドサービス）。監視すべき公開エンドポイントができたら再検討 |
| PostHog | Phase1の実利用者が1人の段階では行動分析の母数がない。App Store/Google Play配信後、他ユーザーが使い始めてから導入 |
| Resend | Supabase Authの組み込みメール機能でPhase1の個人利用には十分。不特定多数へのサインアップ受付段階でメール到達率の問題が出たら乗り換え |
| Better Stack | Sentry+UptimeRobot+ログ管理の統合版。どちらも本格導入していない現時点では時期尚早 |
