# launch-copy.md — 完成品ローンチ用コピー案（構想・2026-07-26）

**前提**：ここに記録するコピーはPhase1（2026-10-01、Web版のみ）のローンチ用ではなく、**完成品（Beacon等を含む将来の姿）のローンチ用**として書かれたもの。Phase1時点ではまだ実現していない機能（Realmスコープでの対話、文脈からの検索等）を前提にした表現が含まれるため、Phase1のマーケティング資料には転用しないこと。

`PRINCIPLES.md`（Lumoraの設計原則5箇条）との対応：
- 「AIには渡さない決定権。」＝ Principle 1「AIは提案者であり、決定者ではない」をそのまま外向けの言葉にしたもの
- 「失わない記憶」（タグライン）＝ Principle 3「知識は破壊しない」（却下も物理削除しない）と直接呼応

## 案①：機能列挙型

```
AIには渡さない決定権。
言葉、文脈、時期から探せる横断検索。
範囲を自在に切り替えられる5色のMarker。
プロジェクトだけを理解したAIと瞬時に対話。
線を引いて分けるだけの、シンプルな整理。

Lumora
失わない記憶。
```

各行が具体的な機能・効能に対応しており、「機能紹介」セクション向き。

- 「プロジェクトだけを理解したAIと瞬時に対話」＝Beaconの「Realmスコープでの対話」構想（`VISION.md`9章「Beaconの対話スコープ」）
- 「言葉、文脈、時期から探せる」＝「文脈」はBeacon（AI理解層）寄り、「時期」は横断検索の日付ソート・絞り込みに対応

## 案②：コンセプト重視型

```

思い出せないを、なくす検索。
散らばった情報を、線一本で整理する。

Lumora

```

より感情に訴える言い方で、行数も少なく抽象度が高い。「トップのキャッチコピー（ヒーロー）」向き。DESIGN.mdの参照プロダクト（Perplexity/Arc寄りの、機能列挙より概念重視のトーン）に近い。

## 組み合わせ案

①と②は対立する案というより役割が違う。ランディングページ等で使う場合：
- ②をヒーロー部分（ページ最上部、一撃で伝える部分）
- ①をその下の機能紹介セクション

という組み合わせ方が自然。
