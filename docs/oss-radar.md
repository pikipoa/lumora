# oss-radar.md — Lumora OSS Radar（構想・2026-07-26）

海外のPKM（Personal Knowledge Management）／AI second brain系OSSを実地調査し、Lumoraへの導入価値で並べたもの。**単なるGitHub Star数の人気ランキングではない**（元記事の指摘通り、人気とLumoraへの価値は別軸）。

## 前提：Lumoraのスタックとの整合性を先に確認

Lumoraの実際のスタックは **Expo（React Native Web）＋Supabase（Postgres/Auth/Storage）＋Vercel＋Sentry**。海外のインディーハッカー定番構成（Next.js＋Tailwind＋shadcn/ui＋tRPC＋Drizzle等）とは**フロントエンドのスタックが根本的に異なる**。そのため：

- shadcn/ui・tRPC・Drizzle ORM・React Query・TanStackは、Next.js前提のライブラリで、Expo/RNへの直接導入はできない（採用するならスタック移行＝書き直しに近い規模になる）。今回のレーダーからは対象外とし、参考程度の記載に留める
- 本レーダーの主眼は、**コードやライブラリをそのまま輸入できるもの**（Postgresスキーマパターン、MCPサーバー実装等）と、**設計思想・UXパターンとして学べるもの**（グラフ表示、自動リンク生成の考え方等）を分けて評価すること

## 🥇 S評価（設計思想を深く参考にすべき）

### 1. claude-obsidian（AgriciDaniel/claude-obsidian）

Obsidian＋Claude Codeで動く自己組織化AIセカンドブレイン。ソースを放り込むとAIが読んで既存知識と自動でリンクし、1つの繋がった知識グラフを作る。Karpathyの「LLM Wiki」パターンがベース。約9,300★（GitHub topics調査時点）。

| 軸 | 評価 | 理由 |
|---|---|---|
| Lumoraとの親和性 | ★★★★★ | Beaconの「Arca同士の関連発見」「時系列ストーリー生成」と直接重なる設計思想。「リンク密度がノート数より価値を決める」という思想はBeaconの目指す方向そのもの |
| 実装コスト | ★★☆☆☆ | Obsidian＋Claude Code前提で直接は使えないが、**自動リンク生成のロジック（PARA/Zettelkasten等の手法選択、リンクの張り方）は設計として輸入価値が高い** |
| UX向上 | ★★★★★ | 「20ページのPDFを1コマンドで8〜15個の連結ノートに変換」という体験は、Beaconのノードマップ構想に直接応用できる |
| 技術的将来性 | ★★★★☆ | MITライセンス、マルチエージェント対応、活発に更新中 |
| コミュニティの勢い | ★★★★★ | 9.3k★は今回調査した中で最大 |

**Lumoraへの応用**：Beacon実装時の「関連発見アルゴリズム」の設計リファレンスとして最優先で読む価値がある。

**Phase2で採用**（Beaconの設計参考として）

## 総括：今回の調査からの示唆

1. **Karpathyの「LLM Wiki」パターンが既に1ジャンルとして定着している**（claude-obsidian、SwarmVault、複数のllm-wiki実装）。Lumoraが2026-07-11に転換した「AI提案→人間確定」の情報フローは、これらの多くが採用する「AIが自動でリンク・整理し続ける」方式とは一線を画す。これはLumoraの差別化ポイントとして明確に主張できる（PRINCIPLES.md Principle 1）
2. **コードの直接流用より、設計思想の参考としての価値が中心**。Lumoraのスタック（Expo/RN＋Supabase）が海外の主流（Next.js系）と異なるため、「そのままインストールする」形の採用はほぼ無い
3. **Beacon実装時の最優先参考資料はclaude-obsidian**（関連発見・自動リンクの実装思想）と**OB1**（MCPサーバー設計）
